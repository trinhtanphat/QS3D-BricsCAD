# Direct Draw quick structural authoring

Status: source implementation for Beam / Slab / Column quick authoring.

## Goal

Reduce repeated numeric input during high-frequency structural authoring without removing the ability to override dimensions for a one-off object.

The primary Ribbon commands remain the quick paths:

- `QS3DDRAWBEAM`
- `QS3DDRAWSLAB`
- `QS3DDRAWCOLUMN`

They inherit dimensions from the active compatible Family when available, otherwise from the first compatible Family, then use guarded projectless fallbacks only when no such Family value is available.

## Quick paths

### Beam

`QS3DDRAWBEAM`

1. Pick start point.
2. Pick end point.
3. QS3D uses Beam Family values directly and creates semantic + native 3D.

Defaults/fallbacks:

- `WidthM`: `0.3 m`
- `HeightM`: `0.5 m`
- `BottomOffsetM`: `0 m`

No Width / Height / BottomOffset numeric prompts are shown on the primary quick path.

Use `QS3DDRAWBEAMADV` to preserve the former three-prompt override flow.

### Slab

`QS3DDRAWSLAB`

1. Pick the closed slab boundary points.
2. Finish the boundary.
3. QS3D uses Slab Family values directly and creates semantic + native 3D.

Defaults/fallbacks:

- `ThicknessM`: `0.12 m`
- `BottomOffsetM`: `0 m`

No Thickness / BottomOffset numeric prompts are shown on the primary quick path.

Use `QS3DDRAWSLABADV` for the former two-prompt override flow.

### Column

`QS3DDRAWCOLUMN`

1. Pick the column center point.
2. QS3D uses Column Family section/height/offset directly, creates the guarded rectangular source footprint, then creates semantic + native 3D.

Defaults/fallbacks:

- `WidthM`: `0.4 m`
- `DepthM`: `0.4 m`
- `HeightM`: `3.6 m`
- `BottomOffsetM`: `0 m`

No Width / Depth / Height / BottomOffset numeric prompts are shown on the primary quick path.

Use `QS3DDRAWCOLUMNADV` for the former four-prompt override flow.

## Safety contract

Quick authoring does not create a second geometry engine. Both quick and ADV paths continue through the same `ExecuteDirect(...)` orchestration:

- real DWG source entity;
- `SemanticCaptureService`;
- Family/instance property assignment;
- scoped semantic regeneration of only the newly-created element;
- existing guarded native builder;
- generated ownership checks;
- `ProjectStateSnapshot` compensation and source/generated CAD cleanup on failure;
- Workspace/selection synchronization after success.

Configured Family values remain validated by `FamilyNumber(...)` / `FamilyFiniteNumber(...)`. Invalid configured dimensions fail closed rather than silently falling back.

Primary Ribbon entries continue to invoke the quick command names. ADV commands are explicit command-line/automation entry points until a separate UX decision adds secondary Ribbon affordances.

## Qualification boundary

This source change reduces prompts; it does not claim exact BricsCAD V25 runtime qualification. Local qualification should verify at least:

- quick Beam needs only two geometry picks and uses the intended active/inherited Family values;
- quick Slab needs only boundary authoring and uses the intended Family values;
- quick Column needs only one center pick and uses the intended Family values;
- each ADV command still exposes all previous numeric overrides and cancel paths;
- quick and ADV paths preserve rollback, Undo expectations, source/generated ownership, Save/Reopen and multi-DWG behavior;
- no unrelated dirty semantic element is regenerated by Direct Draw.

These checks remain within the existing Direct Draw / LOCAL_ONLY BricsCAD V25 qualification boundary; source review is not `LOCAL_PASS`.
